# Instruction-Following 미션 — 분석 및 구현 계획

## 공식 정의 (문제 스펙)
Instruction following statements ask the system to take a certain path, using
objects to specify the trajectory of the path. The response is expected to be a
sequence of waypoints.

예시:
- "Take the path near the window to the fridge."
- "Avoid the path between the two tables and go near the blue trash can near the window."

## questions.json 실제 예시 (15개 씬 x 2개, 총 30개)
- "Go near the stool under the picture and stop at the small table farthest from the columns."
- "First, go to the potted plant furthest from the hookah, then take the path between
  the two columns, and stop at the tray on the table."
- "First, go near the tea table with the elephant figurine on it, then stop at the
  table with the horse figurine on it, avoiding the path between the chair and the
  folding screen."
- "Take the path between the sofa and the coffee table and go to the kettle on the
  dining table, then go to the potted plant between the curtain and the TV."
- "Go to the cup near the TV remote and avoid the path near the cabinet."
- "First, go to the trash can near the cabinet, then go to the folder on the cabinet
  closest to the whiteboard, and finally, to the door near the exit sign."
- (전체 30개는 questions/questions.json 참고, 패턴은 아래 3가지로 수렴)

### 문장 구조 패턴 (파싱 시 구분해야 하는 3종류의 절)
1. **목적지 절(stop clause)** — "go to X", "go near X", "stop at X", "stop by X" →
   순서대로 지나야 할 waypoint. 각 X는 object_reference와 동일한 문법(attribute +
   relation_chain, 예: "the table with the horse figurine on it")으로 하나의 3D
   point로 resolve됨.
2. **긍정 경로 절(positive path clause)** — "take the path between A and B",
   "take the path near Z" → 목적지는 아니고 **반드시 지나가야 하는 경유 지점/영역**.
   "between A and B"면 A-B 중간점 근방을 waypoint로 추가, "near Z"면 Z 근처 한 점을
   경유 waypoint로 추가.
3. **부정 경로 절(negative/forbidden constraint)** — "avoiding the path between A
   and B", "avoid the path near Z" → 목적지도 경유지도 아니고, **경로가 이 영역을
   통과하면 감점**. Waypoint 자체가 아니라 planner의 forbidden-region 제약으로 들어가야 함.

문장 하나에 "First, ..., then ..., and finally, ..." 식으로 최대 3단계 목적지가 이어지고,
그 사이사이에 positive/negative path 절이 끼는 구조. "avoiding"/"avoid"가 있으면
negative, 그 외 "take the path"는 positive로 구분 가능(규칙 기반으로 충분할 듯).

## 채점 (README)
- 배점: **/6점** (세 미션 중 가장 배점 큼 — 1+2+6=9점 중 6점)
- 토픽: `/way_point_with_heading`, `geometry_msgs/msg/Pose2D` **연속 발행(시퀀스)**
  (heading 필드는 이번 챌린지에서 무시됨 - README: "neglect the heading for this year's
  challenge")
- 채점 기준(README 원문): "The score will be calculated based on the actual
  trajectory followed by the robot based on whether it follows the path constraints
  in the command and in the correct order." 감점 요인 3가지:
  1. 순서 위반(deviates from the correct order of constraints)
  2. 제약 미달성(does not achieve the desired constraints) — 예: positive path
     절을 실제로 안 지나감
  3. **금지 구역 통과**(passes through areas it is forbidden to go through) —
     negative constraint 위반
  - 부분점수 있음(0~6)

## 현재 구현 상태 — 전혀 없음
- object_reference/numerical과 마찬가지로 `question_callback`에 이 유형에 대한 분기가
  없음 ("go"/"take the path"/"avoid" 시작 문장도 지금은 무조건 단일 object-reference로
  처리됨)
- `/way_point_with_heading` 자체는 이미 발행되고 있음(`goal_publisher`) - 하지만
  지금은 "탐색 중 다음 프론티어로 이동" 또는 "선택된 단일 object로 접근"용 단발성
  좌표일 뿐, **순서가 있는 다단계 시퀀스+금지구역 회피 경로 생성** 로직은 없음
- forbidden-region 개념 자체가 `coverage_planner`/A* 어디에도 없음(현재 traversability
  grid는 정적 장애물 기반이고, "이 문장에서만 이 영역을 피해라" 같은 질문별 동적 제약을
  넣을 방법이 없음)

## 필요한 작업

### 1. 질문 분기
"go"/"take the path"/"avoid"로 시작(혹은 "first,"로 시작)하면 instruction_following
파이프라인으로 분기. object_reference와 구분 기준: "find"/"the X" 단일 명사구가 아니라
"go to/near", "stop at/by", "take the path" 같은 **이동 동사**가 핵심 - 문장에 이런
이동 동사가 있으면 instruction_following으로 우선 분기하는 게 안전해 보임(순서 중요,
"the X and stop at the Y" 안에도 "the"만 있는 절이 섞여있어서 명사구 패턴만으로는 구분
어려움).

### 2. 문장 파싱 (신규 컴포넌트 필요 - 기존 파서로는 부족)
기존 `LLMQueryParser`/`query_parser.py`는 "하나의 target + 하나의 relation_chain"
구조라 이 미션의 "여러 목적지 절 + positive/negative path 절"을 못 담음. 신규
`instruction_parser.py` 필요:
- 문장을 "First, / then / and finally, / and" 등의 접속사로 절 단위 분리
- 각 절을 3종류로 분류: destination(go to/near, stop at/by) / positive_path(take
  the path) / negative_path(avoid/avoiding)
- destination 절은 기존 target+attribute+relation_chain 파서(`extract_target()`류)
  재사용 가능 - "the X with Y on it", "the X closest to Z" 등 문법이 object_reference와
  동일
- "between A and B" / "near Z" 패턴은 path 절에서 A,B,Z를 각각 target으로 재귀 파싱
- LLM 기반으로 처음부터 만드는 게 규칙기반보다 안전할 수 있음(paper 철학 유지 + 이런
  자유도 높은 다중 절 문장은 정규식으로 커버하기 어려움) - object_reference/numerical
  때와 동일하게 LLM 파싱 + 실패시 규칙 기반 폴백 patttern 유지 권장

### 3. 각 목적지를 3D 좌표로 resolve
`sysnav_node.py`의 기존 selection_job 로직(relation_chain 검증 → attribute_verifier →
gemini_selector) 재사용 - 다만 지금은 "1개 질문 = 1개 target"이라 상태머신이 1회성인데,
이 미션은 "N개의 목적지를 순서대로 resolve"해야 하므로 상태머신에 **목적지 큐/인덱스**
개념 추가 필요 (예: `ctx.destination_queue`, `ctx.destination_index`).

### 4. 각 목적지마다 탐색 필요할 수 있음
object_reference처럼 "장면에 이미 다 관측되어 있지 않을 수 있다" 문제가 목적지마다
반복됨 - i번째 목적지를 못 찾으면 PLAN_EXPLORATION으로 돌아가되, **이미 resolve한
이전 목적지들의 상태(순서, 이미 지나온 waypoint)는 유지**해야 함. 상태머신 재진입성
설계가 object_reference보다 복잡함.

### 5. 경유지(positive path) 처리
"take the path between A and B"의 A, B는 object_reference 방식으로 resolve 후,
중간점(A와 B 사이, 정확히는 통과 가능한 free space 중 A-B를 잇는 선분에 가장 가까운 점)을
계산해 waypoint 시퀀스에 삽입. "near Z"는 Z 주변의 traversable cell 하나를 waypoint로.

### 6. 금지구역(negative path) 처리 — 가장 복잡한 신규 컴포넌트
`coverage_planner`의 A*(`_astar_path` 계열)가 지금은 정적 traversability grid만
씀 - **질문별로 동적 forbidden mask를 추가**해야 함:
- "avoiding the path between A and B" → A, B를 잇는 선분 주변 일정 반경(폭 추정 필요,
  가칭 `INSTRUCTION_FORBIDDEN_CORRIDOR_WIDTH_M`)을 이번 질문 한정 임시 non-traversable로
  마킹
- "avoid the path near Z" → Z 주변 반경을 마킹
- A* cost/blocking mask에 이 임시 마스크를 합성해서 최종 경로가 그 영역을 피해가도록
  강제 - **평소 탐색용 traversability grid 자체는 건드리면 안 됨**(이 질문 끝나면
  원상복구해야 다음 질문에 영향 없음) - `plan_route()`에 optional
  `forbidden_mask` 파라미터 추가하는 방향이 기존 구조(nav_blocking/los_blocking
  분리 패턴)와 자연스럽게 맞음

### 7. Waypoint 시퀀스 발행
- 최종적으로 확정된 waypoint 시퀀스(경유지 포함, 목적지 포함, 순서대로)를
  `/way_point_with_heading`(Pose2D)에 **순서대로 하나씩** 발행
  - 순서가 채점 기준이므로, 로봇이 각 waypoint에 실제로 도달했는지 확인 후 다음 것을
    발행하는 방식이 안전(기존 `goal_publisher`의 "도달 확인 후 다음 목표" 패턴이 있다면
    재사용, 없으면 신규)
- `/selected_object_marker`/`/numerical_response`는 이 미션에서 안 씀

## 재사용 가능한 기존 인프라
- object_reference용으로 만든 relation_chain 검증, attribute_verifier, gemini_selector
  — 각 목적지 절의 object resolve에 그대로 재사용
- `coverage_planner.py`의 A* 경로탐색 - forbidden_mask 파라미터만 추가하면 나머지
  로직(traversability, room-scoping 등) 재사용 가능
- `goal_publisher` — Pose2D 발행 메커니즘 자체는 재사용, 시퀀스 관리 로직만 신규

## 새로 만들어야 하는 것
- `task/instruction_parser.py` (신규) — 문장 → destination/positive_path/negative_path
  절 리스트로 분해, LLM 기반 + 규칙 폴백
- instruction_following 전용 상태머신 확장 (목적지 큐 + 인덱스, 재진입 가능한 탐색-재개)
- `coverage_planner.plan_route()`에 forbidden_mask 파라미터 추가 (질문 종료 시 리셋)
- "between A and B 중간점" / "near Z 근방점" 계산 헬퍼
- waypoint 시퀀스 발행 + 도달 확인 로직

## 우선순위 메모
세 미션 중 배점이 가장 크고(/6) 구현 난이도도 가장 높음(신규 파서 + 신규 상태머신 확장 +
신규 forbidden-region 플래닝). Object Reference의 마커 발행(빠른 수정)과 Numerical
(기존 인프라 재사용 위주)을 먼저 끝내고 마지막에 착수하는 게 합리적.
