# Object Reference 미션 — 분석 및 구현 계획

## 공식 정의 (문제 스펙)
Object reference statements asks the system to find a certain object located in
the scene that is referred to by spatial relations and/or attributes. The response
is expected to be a bounding box around the object and there exists only one
correct answer in the scene (the referred object is unique). The center point of
the bounding box marker will be used as a waypoint to navigate the robot system.

예시:
- "Find the potted plant on the kitchen island that is closest to the fridge."
- "Find the orange chair between the table and sink that is closest to the window."

## questions.json 실제 예시
- "Find the pillow closest to the book on the stool."
- "Find the wall lamp that is between a door frame and a window."
- "Find the clock on the TV cabinet."
- "Find the bowl closest to the knife rack near the trash can."
- "The lantern between the vase and the stone decoration that is closest to the vase."
- "The blue chair that is closest to the cup of coffee."
- (다수 생략, 총 15개 씬 x 2개)

패턴: 대부분 다단계 relation chain(A closest to B, B near C) + 종종 attribute(색상 등)
결합. "Find"로 시작 안 하고 바로 "The X ..."로 시작하는 문장도 있음(japanese_room,
loft 씬) - 파서가 "Find"/"The" 둘 다 처리해야 함.

## 채점 (README)
- 배점: **/2점**
- 토픽: `/selected_object_marker`, `visualization_msgs/msg/Marker` (**단수 Marker**,
  MarkerArray 아님 - 바꾸면 base autonomy/평가 시스템이 조용히 구독 끊김, CLAUDE.md 참고)
- bbox와 ground truth의 겹침 정도로 채점 (0~2점, 부분점수 있음)
- **마커의 center point가 곧 navigation waypoint로도 쓰임** - `docker/README.md`의
  dummy_vlm도 "marker 발행 + `/way_point_with_heading`으로 waypoint도 별도 발행" 둘 다 함

## 현재 구현 상태 — 파이프라인은 다 있는데 마지막 배관이 빠짐

### 되어 있는 것 (이번 세션에 집중적으로 만든 부분)
- `task/llm_query_parser.py` / `task/query_parser.py` — 문장 → target + attributes +
  relation_chain (다단계 관계 체인 지원, "closest to"/"between"/"near" 등)
- `perception/perception_pipeline.py` — YOLO-World 탐지 + confidence 낮은 오검출
  Gemini 재검증(`detection_verifier.py`) + SAM2 세그멘테이션 + LiDAR 3D grounding
- `exploration/coverage_planner.py` + `rooms/room_segmenter.py` — SysNav 논문 기반
  탐색 정책(room 분할, frontier anchor, 거리 가중치 등 다수 버그 수정 완료)
- `scene_graph/scene_graph_manager.py` + `reasoning/spatial_relation_reasoner.py` —
  relation_chain을 hop별로 실제 관측된 물체끼리 검증, edge로 저장, 체인 끝까지 이어지는
  것만 최종 후보로
- `reasoning/attribute_verifier.py` — 속성(color 등) VLM 검증, 후보 1개여도 반드시 확인
  (fail-closed)
- `reasoning/gemini_selector.py` — 최종 후보 여러 개 중 하나 선택

### 빠진 것 — 이게 있어야 점수가 남
`sysnav_node.py` 전체를 grep해도 `selected_object_marker` 문자열이 안 나옴:
- 최종 선택된 object가 확정되면(`consume_future`의 `kind == "selection"` 분기,
  `NAVIGATE_TARGET` 진입 시점) `/selected_object_marker`에 아무것도 발행 안 함
- 지금 발행하는 건 `/sysnav/object_markers`(MarkerArray, 우리가 만든 디버그 전용
  커스텀 토픽 - config.py의 `TOPIC_OBJECT_MARKERS`)뿐이라, **채점 시스템은 이걸 보지 않음**
- `/way_point_with_heading`으로 waypoint 발행은 이미 되고 있음(`goal_publisher.object_approach_pose`)
  - 이 부분은 정상

## 필요한 작업 (상대적으로 작음, 우선순위 1위)

1. `consume_future()`의 `kind == "selection"` 처리부(선택된 object 확정되는 지점)에서:
   - 선택된 object의 3D position + extent_3d(크기)로 `visualization_msgs/msg/Marker`
     (CUBE 등) 생성
   - `/selected_object_marker` 토픽에 발행 (단수 Marker, MarkerArray 절대 금지)
2. Marker 메시지 필드 확인:
   - `header.frame_id` = "map" (다른 시스템과 좌표계 일치 확인 필요)
   - `pose.position` = object 3D 중심
   - `pose.orientation` = identity(w=1)면 충분할 듯
   - `scale` = extent_3d (bbox 크기) - 0이면 기본값 처리 필요(기존
     `scene_graph_rviz.py`의 `OBJECT_MARKER_DEFAULT_SIZE_M` 패턴 참고 가능)
   - `color` = 채점에 영향 없을 듯하지만 RViz 확인용으로 임의 색 지정
3. `/sysnav/object_markers`(디버그용, 전체 물체 목록)는 그대로 유지 - 새 토픽을
   추가하는 것이지 기존 걸 대체하는 게 아님
4. `NAVIGATE_TARGET`으로 넘어갈 때(현재 이미 하고 있는 `object_approach_pose` +
   `goal_publisher.publish()`)는 그대로 유지

## 참고 - 문장 파싱 관련 확인 필요
questions.json에 "Find"로 시작 안 하는 문장이 있음(예: "The lantern between..."). 지금
`_LEADING_COMMAND` 정규식이 "find/locate/..." 같은 명령어만 벗겨내는데, 애초에 "The"로
시작하면 그 문장 전체가 target 파싱 대상이 됨 - 정규식 파서가 이 경우도 잘 처리하는지
재확인 필요 (LLM 파서는 아마 문제없이 처리할 것).
